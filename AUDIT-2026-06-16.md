## 🔴 Critique

### C1 — `studies.delete` laisse des comptes-rendus + PDF PHI orphelins

**`server/routers.ts:650-700`** (vérifié)

La suppression d'étude purge dans l'ordre : objets S3 par instance, `annotations`, `instances`, `series`, `notifications`, `albumStudies`, `studies`. La liste des tables importées **n'inclut ni `reports` ni `reportAddenda`**. Or `reports.studyId` est `notNull().unique()` et stocke indication / technique / résultats / conclusion (**PHI clinique**) + `pdfStorageKey` (PDF nominatif dans S3).

**Conséquence :** après une « suppression » d'étude (censée matérialiser le droit à l'effacement nLPD/RGPD) :

- la ligne `reports` et ses `report_addenda` subsistent en base (orphelins) ;
- le **PDF du compte-rendu reste dans le bucket** (jamais `storageDelete(report.pdfStorageKey)`) → PHI résiduel.

**Correctif :** avant `db.delete(studies)`, charger le report de l'étude → `storageDelete(report.pdfStorageKey)`, `db.delete(reportAddenda).where(eq(reportAddenda.reportId, report.id))`, `db.delete(reports).where(eq(reports.studyId, input.id))`. Ajouter un test de non-régression.

### C2 — `notify*` : exfiltration PHI vers un destinataire arbitraire, sans garde

**`server/routers.ts:1437-1480`** (vérifié)

Les trois mutations `notifications.notifyNewStudy / notifyStatUrgent / notifyReportFinalized` acceptent un **`recipientEmail` libre** + `patientName` (PHI), sont ouvertes à **tout rôle clinique** (`medicalProcedure`), et appellent directement `notify*(input)` **sans `isAllowedRecipient`** et **sans `recordAccess`**. Elles contournent exactement la protection que `sendStudyReport` applique pourtant (allow-list de domaines + audit trail avant envoi). Un utilisateur peut envoyer le nom d'un patient vers n'importe quel domaine externe, sans laisser de trace.

**Correctif :** dans chaque resolver — (1) `if (!isAllowedRecipient(input.recipientEmail, ENV.reportEmailAllowedDomains)) throw FORBIDDEN`, (2) `await recordAccess({ action: "study.email.notify", detail: input.recipientEmail, ... })`. Idéalement restreindre ces endpoints à la boîte RIS interne plutôt qu'à un destinataire libre.

## 🟠 Élevé

### H1 — `fast-xml-parser` 5.2.5 — CVE critique (entity-encoding bypass)

`pnpm audit --prod` → **50 vulns (1 critique, 20 high)**. La critique = `fast-xml-parser` (GHSA-m7jm-9gc2-mpf2), transitive via `@aws-sdk/client-s3@3.907.0`.
**Correctif :** `pnpm up @aws-sdk/client-s3 @aws-sdk/s3-request-presigner`, ou `pnpm.overrides` `"fast-xml-parser": ">=5.3.5"`.

### H2 — Pas de protection CSRF sur les mutations tRPC

`/api/export` est protégé par un check `sec-fetch-site: cross-site` (`index.ts:76-82`), **mais pas `/api/trpc`**. La seule défense est le cookie `sameSite:"lax"`, qui ne bloque pas les POST cross-site auto-submit. Un site malveillant visité par un radiologue authentifié peut déclencher `dicom.import`, suppressions, etc.
**Correctif :** appliquer le même garde `sec-fetch-site === "cross-site"` (déjà écrit) sur `/api/trpc`, ou vérifier `Origin`/`Referer` contre l'allow-list d'hôtes.

### H3 — Brute-force possible sur `auth.login`

`login` n'est couvert que par le limiter global `/api` (**6000 req / 15 min**), bien trop permissif. Pas de compteur d'échecs par compte/IP. bcrypt(12) ralentit mais ne suffit pas.
**Correctif :** limiter dédié strict (5–10 tentatives / 15 min, clé IP+email) + lockout/backoff ; loguer les échecs dans `access_logs`.

### H4 — PHI sortant de Suisse en mode Claude cloud, sans garde de transfert ni de-id pixel

Défaut = **Ollama local (PHI-safe)**, bon. Mais si `AI_BACKEND=claude`, le rendu **serveur** des coupes (`aiSampling.ts` → `renderDicomFrame`) envoie les **pixels bruts** à l'API Anthropic (hors CH/UE). Le caviardage burned-in n'existe que **côté client** (exports email) et n'est **pas** appliqué à ce rendu serveur. Un nom/ID incrusté (US, capture secondaire) peut donc fuiter.
**Correctif :** encadrer contractuellement (DPA / clauses-types art. 9 nLPD) ; garde-fou interdisant Claude pour les modalités à risque de burned-in (US/SC/XC) ou exigeant une redaction serveur ; documenter la base légale.

### H5 — Dépendances directes à CVE high

`axios ^1.12.0` (~12 advisories : proto pollution, SSRF metadata, ReDoS) et `@trpc/server` épinglé `11.6.0` (proto pollution, patché en **11.8.0**).
**Correctif :** `pnpm up axios@latest` (≥1.13) ; bumper `@trpc/{client,react-query,server}` à `^11.8.0`.

### H6 — CI sans gate qualité avant la prod

`.github/workflows/deploy-image.yml` ne fait que build + push GHCR. **Aucun** `pnpm check` / `pnpm test` / `pnpm audit` / lint → une régression ou une CVE part directement en image de prod.
**Correctif :** job `test` (`pnpm install --frozen-lockfile`, `check`, `test`, `audit --prod --audit-level high`) en `needs:` du build.

### H7 — Absence d'en-têtes de sécurité sur le document applicatif

`helmet` absent. Le viewer PHI est servi sans CSP, sans `X-Frame-Options`/`frame-ancestors` (clickjacking), sans HSTS, sans `Referrer-Policy`. (Le `storageProxy` pose bien un CSP sandbox sur les octets DICOM — mais pas le document app.)
**Correctif :** `helmet()` avec `frameguard: deny`, HSTS (prod), CSP applicative. Vérifier que Traefik ne pose pas déjà HSTS en amont.

### H8 — Docker : conteneur root + devDeps en prod

`Dockerfile` ne définit aucun `USER` (app en root) et installe toutes les devDeps en prod (car `server/_core/vite.ts` importe statiquement `vite`).
**Correctif :** `USER node` avant le `CMD` ; isoler le mode dev de vite derrière un import dynamique conditionnel `NODE_ENV` pour repasser à `pnpm install --prod`.

## 🟡 Faible / Qualité

- **M1 — Egress/énumération PHI non audités.** `studies.list` (toute la worklist) et `export.dicomSeries`/`export.pdfReport` n'écrivent pas de `recordAccess`, alors que les autres egress le font. Trou de traçabilité nLPD. → ajouter `recordAccess`.
- **M2 — `annotations.delete`/`listByInstance`/`listBySeries`** (`routers.ts:877-930`) : suppression par `id` brut sans contrôle d'appartenance ni audit (choix mono-cabinet assumé, mais une suppression non tracée reste un manque). → vérifier `userId`/rôle + `recordAccess`.
- **M3 — Anonymiseur DICOM** (`routers.ts:65-98`) : `dcmjs` gère bien Implicit VR + séquences imbriquées (testé, fail-closed), mais `PII_TAGS` (16 tags) omet `OperatorsName`, `StationName`, `DeviceSerialNumber`, `RequestingPhysician`, les **tags privés** (groupes impairs) et overlays 60xx. → passer au profil de base DICOM PS3.15 (`dcmjs` Anonymizer) + suppression des groupes privés.
- **M4 — `env.ts`** : chaque variable a un défaut silencieux (`?? ""`) ; un `JWT_SECRET`/`DATABASE_URL`/`S3_*` manquant ne fait pas échouer le boot (garde-fou runtime tardif seulement). → schéma Zod validé au boot avec `process.exit(1)`.
- **M5 — `orthanc.ts:118-186`** : `qidoSearchSeries`/`wado*`/`stowStore` interpolent des UID **sans** `isValidDicomUid`/`encodeURIComponent`. Non exploitable aujourd'hui (code mort, non appelé ; le chemin live passe par `buildOrthancPath` validé), mais footgun. → valider/encoder ou supprimer.
- **M6 — Injection de prompt IA** (`aiPreanalysis.ts:162`) : antécédents/indication concaténés tels quels. Mitigé (brouillon relu/signé par un médecin, system prompt défensif). → délimiteurs explicites « données, pas instructions ».
- **M7 — Divers :** énumération d'utilisateurs sur `register` (`Email already registered`) ; `cFind.query` (`z.record`) non borné en taille/nombre ; JWT sans `iss`/`aud` (algo HS256 bien épinglé, TTL ramené à 7 j, révocation `sessionVersion` OK) ; E2E Playwright minimal (1 smoke) ; pas de `HEALTHCHECK` Docker ; `findAvailablePort` peut désync OAuth en déploiement direct (sans effet derrière Traefik).

## ✅ Corrigé depuis l'audit initial — points positifs confirmés

- **Anonymisation patient réparée** : `studies.anonymize` met bien à jour la table `patients` (nom/ID/dateNaissance via FK interne), tracé et testé. _(était le 🔴 #1 de l'audit initial)_
- **Anonymiseur fail-closed** via `dcmjs` : Implicit VR + séquences imbriquées gérés, throw si parsing échoue (jamais de bytes bruts stockés). Avertissement burned-in dans l'UI + outil de caviardage pixel pour les exports.
- **Audit trail réel** : table `access_logs` append-only, `recordAccess()` appelée sur view/anonymize/delete/cstore/email/ai/report/mpr ; export CSV admin-only ; immuabilité (aucun UPDATE), purge à plancher 30 j.
- **RBAC durci** : `MEDICAL_ROLES` exclut `user` ; actions destructrices (`delete`, `cMove`, `cStore`, `audit.export`, `purge`) en `strictAdminProcedure` ; `pacsServers` re-gated admin + scopé `userId`.
- **Session** : secret JWT ≥ 16 char fail-closed, HS256 épinglé (pas d'alg-confusion), TTL 7 j, révocation serveur via `sessionVersion`, bcrypt(12), login anti-énumération.
- **Réseau** : AET strictement validé/encodé (`safeAeTitle`), proxy DICOMweb exemplaire (grammaire stricte anti-traversal, reconstruction segment par segment), storageProxy auth+rôle+CSP sandbox, rate-limiting appliqué, upload borné 60 Mo + fail-closed, **pas d'injection SQL** (Drizzle paramétré partout), cibles upstream depuis l'ENV only (pas de SSRF d'hôte).
- **Anti-IDOR antériorités** : `assertSamePatientStudies` compare la FK interne `patients.id` (immunisé contre collisions de PatientID DICOM).
- **Emails** : TLS forcé en prod, sujets non-nominatifs, échappement HTML (`esc()`), allow-list destinataires sur `sendStudyReport`. Notifications RIS ciblent la boîte RIS, jamais l'auteur.
- **IA** : défaut Ollama local, aucun identifiant patient dans le prompt, system prompt défensif, timeout 180 s, rate-limit 30/h, immuabilité du CR signé (addenda append-only).
- **Secrets** : `.env` gitignored et jamais commité (historique propre), `.env.example` 100 % placeholders, aucun secret en dur, `.env` exclu de l'image. `drizzle-orm` 0.45.2 (CVE SQLi patché). 1336 tests verts couvrant anonymiseur + RBAC.
