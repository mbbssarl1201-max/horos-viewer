## 🔴 Critiques (vérifiés manuellement)

### C1 — Fuite PHI inter-patients : états React non réinitialisés au changement d'étude

`client/src/pages/Viewer.tsx`, `client/src/components/ReportPanel.tsx`. Route `/viewer/:studyId?`
sans `key` → `Viewer` reste monté en navigation viewer→viewer (ex. « Ouvrir » une antériorité).
Aucun reset de `selectedSeries` (auto-select gardé par `!selectedSeries`), `reportKeyImages`,
`redactionsByImage`, ni des sections/`antecedents` de `ReportPanel`. Conséquences : coupes du
patient A sous l'en-tête de l'étude B ; images-clés / texte de A joints au CR signable/envoyable
de B. **Fix :** `key={study.id}` sur ReportPanel (+ sous-arbre viewer), `useEffect(reset…, [studyId])`,
auto-select conditionné à « série ∈ étude courante ».

### I1 — `sendStudyReport` émet un CR par email sans exiger de signature en base

`server/routers.ts:1366` (medicalProcedure), `server/report/sendStudyReport.ts`. Prend les 4
sections + `signature` (string libre) de l'input client, ne lit pas la table `reports`, ne vérifie
pas `status==="signed"` (seule garde : série∈étude). Un `technician` peut émettre un CR nominatif
sans signature médecin réelle, contournant le verrou d'immuabilité du routeur `reports`.
**Fix :** exiger un `reportId` signé en base, lire sections/`aiAssisted` depuis la DB, passer en
`adminProcedure`, dériver `signature` du `signedBy`.

## 🟠 Importants

- **I-email** — Nom patient en clair dans sujets/corps d'email RIS + PDF nominatif vers `to` arbitraire
  (`server/email.ts`, `server/routers.ts`). Risque si SMTP non interne / `SMTP_INSECURE`. Fix :
  interdire `SMTP_INSECURE` en prod + TLS forcé, retirer le nom du sujet, allow-list de domaines.
- **I-claude-timeout** — `generateViaClaude` sans `AbortController`/timeout (la branche Ollama l'a)
  (`server/report/aiPreanalysis.ts`). Fix : `signal` + timeout.
- **I-drizzle** — `drizzle-orm@0.44.6` CVE SQLi (fix ≥0.45.2). Vecteur non instancié (pas de
  `sql.raw`/`identifier` sur entrée client) mais ORM d'une app patient. Fix : bump.
- **I-tests** — Aucun test serveur sur signature/immuabilité/addendum du CR ni sur l'IDOR antériorité.
- **I-assertSamePatient** — garde anti-IDOR antériorité compare le `PatientID` DICOM ; collision
  d'ID inter-sources = garde trompée. Fix : comparer aussi la FK interne `patients.id`.

## 🟡 Mineurs

Anonymisation « métadonnées seulement » (annotations burned-in non couvertes → avertir l'UI) ·
fuites GPU/mémoire client (`renderingEngine.destroy()` conditionnel, `redactionsByImage`/MediaRecorder
non purgés) · `anthropicModel` défaut = ancien id · `S3_REGION=us-east-1` (signal de résidence) ·
image Docker en root · cookie `sameSite:"none"` (héritage Manus) · upload `fileData` sans borne
`.max()` (DoS mémoire) · `register` public (gated par AUTH_MODE) · bornes zod manquantes sur
`studies.list`/`orthanc.cFind` · double `adminProcedure` (shadowing trpc.ts vs routers.ts).
